# Friends Table 카드·사운드 동기화 검증

기준 커밋: b01e1fe3defc75cb64d63ff02e710823bed320b1. 2026-11-10 KST.

## 확인된 원인과 증거 범위

- CALL은 `useGameAudio.ts`에서 예전 `chips-bet.wav`에 연결돼 있었다. RMS −32.07 dBFS로 새 `bet-user.wav`(−19.50)보다 약 12.6 dB 작았다. 미리듣기도 같은 예전 파일을 사용했다. 요청한 칩 음원으로 연결을 수정했다.
- CHECK 단독 이벤트의 파일은 이미 `check-user.wav`였다. 카드 파일로의 폴백이나 별도 기본 액션 재생 경로는 소스에서 발견되지 않았다. 체크/콜로 스트리트가 종료되면 같은 업데이트에 액션과 카드 공개 이벤트가 함께 생성됐고, 기존 우선순위(card 60, check 40/call 45)가 카드음을 먼저 재생했다. CHECK 출력은 기본 마스터 0.5 × 이벤트 0.3 = 0.15였고 카드 공개는 0.30이었다. 정상 카드음이 액션음보다 먼저, 더 크게 들리는 경로를 테스트로 재현했다. 소스의 이 결함과 CALL 매핑 오류는 확인했지만, 사용자가 청취한 APK에서 모든 CHECK 소음의 원인이 이것 하나였다고 단정하지 않는다. 해당 실기기의 오디오 녹음/실행 트레이스는 확보하지 않았다.
- 화면은 `PlayingCard`의 자체 effect로 360ms 애니메이션을 시작하고, 소리는 별도 우선순위 큐에서 시작했다. 플랍은 75ms 간격으로 3개 애니메이션이 겹치고 효과음은 스트리트당 한 번이었다. 서로 시작 시각을 공유하지 않았다.
- 카드 prop 변경/컴포넌트 마운트가 곧 애니메이션 시작 조건이었다. 상대의 비공개 카드는 같은 undefined 값이므로 다음 핸드 배분을 일관되게 표현할 수 없었으며, 복원된 공개 카드가 마운트되면 새 공개처럼 애니메이션될 수 있었다.
- 큐의 1.5초 액션 만료는 길어진 정상 카드 공개 뒤의 액션을 누락시킬 수 있어 5초로 조정했다. 무제한 잔여 재생은 허용하지 않으며 핸드 변경·연결 끊김·background·미리듣기 전환에서 취소한다.

## 수정 방식

테이블 큐는 서버 이벤트 순서를 유지한다. CHECK/CALL 이후 실제로 공개되는 카드음은 제거하지 않고 액션음 다음에 배치한다. `SoundEvents`가 핸드/카드 인덱스로 중복 방지 키를 생성하며 플랍은 3개의 개별 공개 항목을 만든다. `CardPresentation`은 각 항목의 재생 시작 콜백에서 화면에 카드와 모션을 제공한다. 네이티브 seek 완료 후 `play()`와 시각 시작 콜백이 같은 JS 실행 단계에서 호출된다. 큐는 음원 완료와 애니메이션 최소 시간 모두를 기다린다. 일반 게임에서 빠른 CHECK/CALL을 서로 끊지 않고 순서대로 재생한다. 미리듣기는 기존처럼 마지막 선택 우선이다.

음소거 상태에서도 시각 항목은 무음으로 진행한다. 네이티브 준비/seek가 불가능하면 뒤늦은 카드음을 재생하지 않고 시각 연출만 진행한다(진행 중 seek가 200ms 초과 시 무음 전환). 이미 끝난 플레이어 재사용, 비동기 볼륨 setter, seek 취소 잠금, 결과음 대기 예산에 대한 기존 회귀 테스트를 유지했다. 알림은 기존 별도 lane을 사용한다.

새 핸드의 홀 카드 전체는 하나의 360ms 모션과 딜링음 한 번을 공유한다. 상대 비공개 카드도 같은 배분 모션을 사용한다. 좌석별/카드별 지연을 제거했다. 복원/재접속/이전 리비전은 연출을 재실행하지 않는다. 감소된 동작 설정에서는 카드가 정적으로 표시된다.

| 대상 | 변경 전 | 변경 후 |
| --- | --- | --- |
| 홀 카드 한 장 | 360ms | 360ms 유지 |
| 홀 카드 시작 | 상대 두 번째 카드 +70ms, 내 두 번째 카드 +100ms | 전 좌석·두 카드 동시 시작, 지연 0 |
| 플랍 한 장 | 360ms | 540ms |
| 플랍 시작 간격 / 전체 명목 시간 | 75ms / 510ms | 540ms / 1,620ms |
| 턴·리버 한 장 | 360ms | 540ms |
| 재생 큐 tick | 100ms | 16ms |

위 시간은 명목 타이밍이며 실제 화면 프레임과 네이티브 오디오 출력에는 장치 지연이 있을 수 있다. 서버 진행 시간, runout, 턴 제한시간과 서버 실행 코드는 수정하지 않았다. 사용자 C항을 우선하여 E-5의 홀 카드 1.5배 증가는 적용하지 않았다.

## 최종 음원과 음량

| 이벤트 | 파일 | 이전 RMS dBFS | 보정 후 RMS dBFS |
| --- | --- | ---: | ---: |
| CHECK | check-user.wav | −17.56 | −17.67 |
| CALL / BET | bet-user.wav | −19.50 (이전 CALL 파일은 −32.07) | −18.00 |
| RAISE | raise-user.wav | −21.77 | −19.00 |
| ALL-IN | allin-user.wav | −21.92 | −19.00 |
| DEAL / 플랍 각 장 / 턴 / 리버 | deal-user.wav | −29.43 | −22.00 |
| SHUFFLE | shuffle-user.wav | −33.69 | −24.00 |
| FOLD | cards-fold.wav | 원본 유지 | 원본 유지 |
| 팟 획득 | pot-collect.wav | 원본 유지 | 원본 유지 |
| 승리 | win.wav | 원본 유지 | 원본 유지 |
| 내 차례 / 시간 경고 | turn.wav / warning.wav | 원본 유지 | 원본 유지 |

6개 사용자 제공 MP3에서 다시 디코딩해 mono PCM16/44.1kHz로 보정했다. 길이는 유지하고 트리밍하지 않았다. limiter의 sample peak 상한은 −3 dBFS, attack 1ms, release 10ms, 자동 makeup 비활성, latency 보상 활성이다. CHECK는 이미 RMS가 높아 파일 자체를 더 크게 만들지 않고 짧은 피크를 정리했다. 파일별 필터·입출력 SHA-256·4배 업샘플링 피크·전후 RMS는 `audio-sync-audit.json`에 기록했다. 이전 변환에서 0 dBFS에 닿았던 bet/raise/deal/all-in도 보정 결과 포화 샘플 0개다. 원본 녹음에 이미 존재하는 왜곡을 복원했다는 뜻은 아니다.

새 사용자 기본 마스터는 0.5 → 0.75. CHECK 기본 이벤트 gain은 0.3 → 0.65, DEAL은 0.65 → 0.8, 공개음은 0.6 → 0.8. 다른 기본 이벤트 gain은 유지했다. 저장된 마스터·개별 gain·음소거 값은 덮어쓰거나 마이그레이션하지 않는다. 실제 Expo player.volume은 `min(0.8, master × eventGain × 1.5)`로 설정한다. 이는 기존 설정에도 상한 전까지 약 +3.52 dB 보정을 제공하며 0은 계속 0이다. 마스터/이벤트를 100%로 강제하지 않는다. 출력 상한 0.8은 가장 큰 테이블 음원과 알림 음원의 4배 업샘플링 피크가 동시에 정합되어도 합산 최대 −0.37 dBFS가 되도록 측정에 근거해 정했다. OS나 다른 앱의 추가 믹싱은 이 검증 범위 밖이다.

## 수정 파일

- `apps/mobile/src/services/cardPresentation.ts`: 공통 시각 상태, 360/540ms, 복원·중복·오래된 콜백 보호.
- `apps/mobile/src/services/soundEvents.ts`: 카드별 공개 이벤트와 한 번의 홀 카드 배분.
- `apps/mobile/src/services/audioScheduler.ts`: 순서 보존, 시각/음원 공동 시작과 완료, 무음 진행·취소.
- `apps/mobile/src/services/soundCatalog.ts`: 음량 보정, 기본값, 액션 대기 예산.
- `apps/mobile/src/hooks/useGameAudio.ts`: CALL 매핑, 공통 미리듣기/게임 플레이어, 시각 상태 연결.
- `apps/mobile/src/components/PokerCards.tsx`, `PokerTable.tsx`, `apps/mobile/src/screens/GameScreen.tsx`: 공유 모션과 공개 시점 렌더링.
- 사용자 음원 WAV 6개, 관련 서버/모바일 테스트 5개 및 이 문서/음원 감사 JSON.

## 검증

- 전체 서버 테스트 167개, 모바일 테스트 18개 통과(총 185개).
- 모든 workspace TypeScript 검사 통과.
- Android/iOS Expo export 성공. 양 플랫폼 번들의 자산 SHA-256 대조.
- 6개 보정 음원의 길이·PCM 디코딩·SHA-256·포화 샘플·4배 업샘플링 피크 검사 통과.
- 요청 외 기존 WAV 파일 및 서버 실행 코드의 Git 기준 동일성 확인.
- CHECK/CALL/RAISE/ALL-IN 실게임 매핑, 빠른 번갈아 입력, 정상 카드음 유지, 세 장 플랍 타이밍, 홀 카드 동시 배분, 재접속/중복/지연 seek, 음소거/저장 gain, 승리/셔플의 기존 회귀 테스트 포함.
- EAS 빌드 및 Railway 수동 배포는 하지 않았다. 새 APK의 실제 스피커 청취와 장치 영상/오디오 지연 측정은 수행하지 않았다.
