# Web/PWA 광고·수익화 사전 분석

2026-11-12. 현재 코드 확인과 공식 자료 조사만 수행. 광고 SDK 설치·계정 신청·외부 배포 없음.

## 현재 상태

mobile/package.json과 앱 소스에 모바일 광고 SDK, 보상형 광고, 리바이 요청/승인 구현은 없다. 기존 SDK의 웹 호환성을 평가할 대상 자체가 없다. 현재 `resetChips`는 방장의 전체 칩 초기화이며 광고 완료나 개별 리바이와 연결되어 있지 않다.

## 플랫폼별 가능성

AdMob은 모바일 앱 SDK 중심이므로 미래에 도입하더라도 Expo Web 번들에 그대로 포함시키는 방식은 권장하지 않는다. native SDK와 웹 광고 스크립트를 `.native.ts`/`.web.ts` 경계로 분리하고 공통 UI에는 결과만 전달한다. [AdMob 공식 플랫폼 안내](https://developers.google.com/admob)

웹은 Google Ad Manager의 Google Publisher Tag 보상형 광고 같은 구현을 검토할 수 있다. 공식 예제는 준비·종료·보상 이벤트 및 사용자 동의를 요구하며, 지원하지 않는 환경에서는 slot 생성 결과가 null일 수 있다고 설명한다. 모바일 최적화 페이지 조건도 있으므로 PC/iOS/PWA에서 동일한 광고 공급이나 노출을 보장할 수 없다. 이는 기술적 후보이며 계정 승인·광고 공급·매출 가능성이 확인된 결과가 아니다. 일반 웹 디스플레이 광고 역시 해당 사이트 심사·정책·배치 적합성을 확인한 뒤 결정한다. [GPT 보상형 광고 예제](https://developers.google.com/publisher-tag/samples/display-rewarded-ad)

## 포커와 정책

무료 가상 칩, 환전·현금 베팅·현금성 경품이 없다는 사용자 설명을 기준으로 조사했다. Google Publisher Restrictions의 online gambling 정의는 실금전 또는 가치 있는 것을 걸고 금전/경품을 얻을 기회를 제공하는 콘텐츠를 다룬다. 설명된 모델과 이 정의에는 차이가 있다는 해석은 가능하지만, **포커라는 게임 유형만으로 승인/거절을 단정할 수 없다**. 국가·이용자 연령·실제 칩 거래/경품 구조·배치·플랫폼별 별도 규칙을 제출 시점에 재확인해야 한다. 광고로 이 게임을 홍보하는 Google Ads 정책과, 게임 내부에서 타사의 광고를 게재하는 퍼블리셔 정책을 혼동하지 않는다. 제한 대상 인벤토리는 광고 공급이 줄거나 없을 수 있다. [Google Publisher Restrictions](https://support.google.com/publisherpolicies/answer/10437795)

## 게임과 분리하는 구현 원칙

- 광고 로드·시청·실패·닫기·미지원·차단·타임아웃을 모두 종료 가능한 상태로 처리한다. 광고 차단기 탐지 자체를 게임 참가 조건으로 만들지 않는다.
- 활성 턴이나 액션 버튼 위에 광고를 배치하지 않는다. 광고가 서버 타이머를 멈추거나 상대를 대기시키지 않도록 한다.
- 광고 결과는 게임 명령의 인증/권한·방장 승인·칩 계산을 대체하지 않는다. 광고 실패/미지원이어도 기존 게임과 승인 경로는 진행 가능해야 한다.
- 기본 진행과 무관한 선택적 광고를 먼저 검토한다. 실제 보상을 설계한다면 광고사 보상 정책·사용자 동의와 별도 서버 검증/중복 방지를 먼저 정의하고, 클라이언트 완료 이벤트만으로 칩을 지급하지 않는다.
- 보상형 광고를 도입하면서 광고 시청과 보상 관계를 모호하게 표시하지 않는다. 별도 보상 정책이 없다면 단순 광고 노출을 보상형 상품으로 가장하지 않는다.
- 제3자 스크립트는 웹 인증 토큰과 같은 origin 보안에 영향을 줄 수 있다. 공급자 공식 삽입 방식, CSP, 동의/개인정보 처리를 검토하고 광고 진단 로그에 사용자 토큰·카드·친구 정보를 남기지 않는다.

## 구현 전 남은 결정

1. 개별 리바이의 요청 조건, 방장 승인, 횟수/금액, 적용 시점을 기존 전체 초기화와 구분해 정의한다.
2. 게임을 방해하지 않는 위치와 선택적 광고 목적을 정하고 플랫폼 적합성 심사를 확인한다.
3. 공급 없음·차단·취소·오프라인·늦은 콜백·중복 콜백에서 게임이 그대로 진행되는지 테스트한다.

현재 권장 사항은 Web/PWA 기능 이식을 먼저 완료하고 광고는 별도 변경으로 검토하는 것이다. 설치하거나 특정 사업자로 확정할 근거는 아직 없다.
