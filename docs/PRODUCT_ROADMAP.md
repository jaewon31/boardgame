# 친구 전용 홀덤 앱 제품 로드맵 (피드백 기반)

작성일: 2026-10-20
연관 문서: [USER_FEEDBACK.md](./USER_FEEDBACK.md)

> 이 문서는 **구현 현황을 검증하지 않은 우선순위 가설**이다. Codex는 실제 저장소 코드를 읽고 각 항목을 구현됨/부분 구현/미구현/확인 불가로 분류해야 한다.

## P0 — 공개 테스트 전 필수

1. **게임 상태 신뢰성**: 서버 권위의 카드 분배, 베팅 유효성, 팟·사이드팟 분배, 타이 판정. 경계 사례 단위 테스트.
2. **재접속 복구**: 연결이 끊겨도 플레이어 자리·칩·현재 핸드 상태를 복구하고 중복 베팅 방지.
3. **비공개 방 접근**: 초대 코드/링크와 방 권한, 승인되지 않은 참가자 차단.
4. **핸드 도중 광고 금지**: 광고로 다른 플레이어의 턴을 막거나 게임 진행을 지연시키지 않음.
5. **게임 기록 정확성**: 서버 이벤트를 기준으로 핸드·칩 변동 로그 저장, 새로고침/재접속에도 일관성 보장.
6. **기본 보안**: 방 접근 검증, 입력값 검증, 클라이언트의 임의 칩 수정 차단.

## P1 — MVP 경쟁력

1. **방장 게임 운영**: 블라인드, 바이인, 리바인 요청/승인, 리바인 칩 수량.
2. **친구 전적**: 경기별 로그, 승률 및 상대 전적. 지표 정의와 표본 수 표시.
3. **빠른 온보딩**: 최소 단계로 방 생성·참여, 모바일 가독성.
4. **게임 속도 설정**: 턴 타이머, 타임아웃 시 안전한 자동 행동.
5. **공정성 설명**: 셔플 방식, 기록 열람, 테스트 가능한 판정 규칙.

## P2 — 공개 출시 후 검증

1. **리액션 및 소셜 기능**: 이모티콘, 간단한 테이블 상호작용.
2. **PC·태블릿 UX**: 화면 크기별 테이블 레이아웃 개선.
3. **음성 채팅**: 사용자 수요·운영비·안전성 검증 후 검토.
4. **광고 수익화 실험**: 비게임 구간, 빈도 제한, 대기 시간 영향 측정. 리바인 강제 전면광고는 기본안으로 확정하지 않음.
5. **고급 통계**: 충분한 경기 데이터가 있을 때만 의미 있는 지표 제공.

## 출시 전 테스트 시나리오

- 여러 명 동시 올인과 사이드팟 분배.
- 동률·킥커·스트레이트·플러시 경계 사례.
- 베팅 중 앱 백그라운드/네트워크 끊김 후 복귀.
- 리바인 승인 직후 재접속, 중복 승인/중복 칩 지급 방지.
- 방장이 나가거나 기기를 바꾼 경우 권한 및 방 상태.
- 마지막 플레이어의 폴드, 타임아웃 자동 행동.
- 동일 방의 여러 플레이어가 동시에 액션을 제출하는 경우.
- 광고 표시 시 다른 플레이어의 게임 진행 영향.
- 종료 후 경기 로그, 승률, 칩 합계 일관성.

## Codex에 요청할 분석

1. 현재 앱의 클라이언트/서버 구조와 관련 코드 위치 파악.
2. P0/P1/P2 각 항목의 **실제 구현 상태**와 근거 파일/함수 표시.
3. 위험도가 큰 결함 5개 및 재현 방법 제안.
4. 작은 단위로 작업을 분리하고 난이도(낮음/중간/높음)와 선행 조건 작성.
5. 우선 분석만 수행하고 **사용자 승인 전 코드 수정 금지**.
6. 스토어 정책·광고 정책·개인정보 및 현금성 게임 위험은 별도 검토 항목으로 기록.
